# RADIAN GROUP — сайт с интерактивной 3D-моделью

Новая версия radian.kg. Комплекс показан 3D-моделью, с которой можно работать:

- навести на окно — увидеть тип квартиры;
- нажать — открыть карточку;
- «Планировка в 3D» — камера влетает в здание, этажи выше снимаются срезом, на перекрытии вырастает 3D-планировка.

Каждый раздел меню задаёт свой ракурс. На главной камера облетает комплекс по мере прокрутки.

SEO-аудит и план работ — в [SEO.md](SEO.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173 — сборка + слежение + автообновление
npm run build      # продакшн-сборка в dist/
npm run preview    # продакшн-сборка + локальный сервер
node scripts/check-seo.mjs   # проверка мета-тегов, H1, JSON-LD, ссылок в dist/
```

Нужен Node 20+. Для пересборки карты района (`npm run osm`) — Python 3.

### Публикация демо на GitHub Pages

```bash
npm run deploy    # сборка в подпапку /radian-kg/ (noindex) и публикация в ветку gh-pages
```

Демо: https://seitek2002.github.io/radian-kg/. Оно закрыто от индексации (`noindex` + `Disallow`), чтобы не конкурировать в поиске с настоящим radian.kg.

Сборка для стенда, закрытая от индексации:

```bash
SITE_ORIGIN=https://staging.example.kg node scripts/build.mjs --noindex
```

## Как устроено

Пользователь только листает страницу. Страница состоит из секций двух видов:

| Секция | Что на экране |
|---|---|
| сцена (`.scene`, `data-shot`) | 3D-модель на весь экран, сбоку короткий текст; у сцены свой кадр камеры, время суток и подписи |
| лист (`.sheet`) | плотный фон и содержимое во всю ширину: карточки планировок, чертежи, вопросы, визуализации |

Между сценами камера движется вместе с прокруткой (`src/client/scene/app3d.js`, словарь `SHOTS`). Управления моделью мышью нет: это сделано намеренно, по просьбе заказчика. Справа есть список глав страницы, внизу справа — кнопки времени суток.

- **Сначала HTML.** `scripts/build.mjs` собирает все страницы из `src/pages/render.js` в статический HTML: текст, мета, JSON-LD. Без JS и без WebGL сайт работает, фоном служит проектная визуализация.
- **Переходы без перезагрузки.** `src/client/router.js` подменяет `<main>`, камера перелетает к первому кадру новой страницы. На «Контактах» камера заходит в офис продаж.
- **3D грузится отдельным чанком**, пока на экране заставка с логотипом и процентами.

### Модель

- **Здание** (`src/client/scene/complex.js`, размеры в `src/data/building.js`) построено по чертежам: оси 1–7 и А–Д, отметки этажей (+8,400; +48,000; +51,300), контуры секций. Фасады — по визуализациям: белые пилоны и «корона» башни, коричневые панели с перфорированными вставками, стопка балконов в углу, стилобат с порталами и скошенными откосами. Восточный корпус — зеркало западного.
- **Окна** — шейдер «комнаты за стеклом» (`materials.js`): в каждом окне видны стены, шторы, ночью свет. Геометрии комнат нет.
- **Город** (`world.js`) — реальные улицы, дома, газоны, ряды деревьев и арыки из OpenStreetMap: `data-src/osm-raw2.json` → `npm run osm` → `src/data/context.json`.
- **Участок** (`site.js`) — парковки, двор с детской площадкой и беседками, сад, вывески первого этажа, интерьер офиса продаж. Состав взят с radian.kg и визуализаций, точное размещение условное.
- **Разрез этажа** — на странице планировки здание срезается на её этаже, на перекрытии лежит проектный чертёж (`public/assets/floors/`), квартира подсвечена золотом. Положение квартир на этаже взято с чертежа (`LAYOUT` в `src/data/building.js`).

### Почему не лагает

- Вся тяжёлая работа сделана под заставкой: геометрия, отражения для каждого времени суток, компиляция шейдеров.
- При загрузке замеряется реальное время кадра на видеокарте (с `readPixels`, иначе замер врёт) и выбирается уровень качества: `high` (затенение в углах, свечение), `medium` (свечение), `low` (без пост-обработки). На встроенной графике это `low`.
- Кадр рисуется только при изменениях. Тени пересчитываются только по запросу. Когда сцену целиком закрыл лист, рендер стоит.
- Замер на Intel Iris Xe, прокрутка всей главной за 14 секунд: обычный кадр 8,3 мс, 99% кадров быстрее 16,7 мс.

### Дизайн

Стили написаны по правилам скилла Hallmark: все цвета и шрифты идут через токены (`src/styles/tokens.css`), бренд RADIAN сохранён (графит, слоновая кость, золото; Montserrat и Golos Text). Проверка: `node <hallmark>/scripts/sloplint.mjs src/styles/main.css --genre atmospheric --render --url http://localhost:5173/`.

Отладка сцены отдельно от сайта: `npm run devscene`, затем открыть `.preview-dev/index.html` через любой статический сервер.

## Что нужно от клиента

1. **Какой корпус жилой.** По чертежу в одном корпусе 116 квартир, ровно столько указано в проекте на оба «жилых блока». Похоже, блоки — это две секции одного корпуса, а второй корпус — апарт-отель на 114 номеров. Это нужно подтвердить: от ответа зависит, что показывать на втором корпусе.
2. **Чертежи фасадов и первого этажа.** Планы 3–16 этажей есть, фасадов и плана первого этажа нет: размещение магазинов, ресторанов и входа в паркинг показано условно.
3. **Генплан участка.** Парковки, двор и проезды расставлены по визуализациям; посадка здания на участке и границы участка оценочные.
4. **Офис продаж.** Интерьер на модели условный; адреса и часов работы офиса нет.
5. **ID аналитики** (GTM, Метрика) в `SITE.analytics`, онлайн-форма, перенос кыргызской, английской и арабской версий (см. SEO.md).

## Деплой (nginx)

`dist/` — статический сайт:

```nginx
server {
  server_name radian.kg;
  root /var/www/radian/dist;
  location / { try_files $uri $uri/ =404; }
  error_page 404 /404.html;
  location /assets/js/  { expires 1y; add_header Cache-Control "public, immutable"; }
  location /assets/css/ { expires 1y; add_header Cache-Control "public, immutable"; }
  location /assets/     { expires 30d; }
  gzip on; gzip_types text/css application/javascript application/json image/svg+xml;
}
server { server_name www.radian.kg; return 301 https://radian.kg$request_uri; }
```

JS и CSS имеют хэш в имени, поэтому их можно кэшировать навсегда.
