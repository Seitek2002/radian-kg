# RADIAN GROUP — сайт с интерактивной 3D-моделью

Новая версия radian.kg. Комплекс показан 3D-моделью, с которой можно работать:

- навести на окно — увидеть тип квартиры;
- нажать — открыть карточку;
- «Планировка в 3D» — камера влетает в здание, этажи выше снимаются срезом, на перекрытии вырастает 3D-планировка.

Каждый раздел меню задаёт свой ракурс. На главной камера облетает комплекс по мере прокрутки.

SEO-аудит и план работ — в [SEO.md](SEO.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173 — сборка + слежение + автообновление
npm run build      # продакшн-сборка в dist/
npm run preview    # продакшн-сборка + локальный сервер
node scripts/check-seo.mjs   # проверка мета-тегов, H1, JSON-LD, ссылок в dist/
```

Нужен Node 20+. Для пересборки данных (`npm run walls`, `npm run osm`) — Python 3 с `opencv-python`, `numpy` и `Pillow`.

### Публикация демо на GitHub Pages

```bash
npm run deploy    # сборка в подпапку /radian-kg/ (noindex) и публикация в ветку gh-pages
```

Демо: https://seitek2002.github.io/radian-kg/. Оно закрыто от индексации (`noindex` + `Disallow`), чтобы не конкурировать в поиске с настоящим radian.kg.

Сборка для стенда, закрытая от индексации:

```bash
SITE_ORIGIN=https://staging.example.kg node scripts/build.mjs --noindex
```

## Как устроено

| Раскладка | Где | Что на экране |
|---|---|---|
| `hero` | первый экран главной | 3D на весь экран, текст поверх |
| `split` | О проекте, Планировки, Расположение… | текст слева, модель справа; на телефоне модель сверху, текст снизу |
| `stage` | страница квартиры | 3D-планировка сверху на всю ширину, ниже характеристики и чертежи |

- **Сначала HTML.** `scripts/build.mjs` пререндерит все страницы из `src/pages/render.js` в статический HTML: текст, мета, JSON-LD. Без JS и без WebGL сайт полностью работает, вместо сцены показываются визуализации.
- **Переходы без перезагрузки.** `src/client/router.js` подгружает HTML следующей страницы и меняет `<main>`. Сцена живёт непрерывно, камера перелетает к новому ракурсу.
- **Секция → ракурс.** У каждой секции есть `data-view` (ракурс камеры) и `data-layout` (раскладка). Секция в зоне чтения переключает сцену (`src/client/page.js`).
- **3D-движок** (`src/client/scene/`, Three.js) грузится отдельным чанком после `load`. Пока он готовится, предзагрузчик показывает проценты и текущий этап.

### Почему не лагает

Вся тяжёлая работа сделана в предзагрузке, во время анимаций ничего не создаётся и не компилируется:

1. Чанк движка скачивается с прогрессом по байтам.
2. Город, комплекс и подписи строятся частями, с паузами между ними.
3. Отражения неба для дня, вечера и ночи считаются заранее.
4. Все шейдеры компилируются заранее, включая скрытые: планировку, режим стройки, перекрытия, ночные огни. Проверка в dev: `renderer.info.programs` при переходах не растёт.
5. Тест производительности выбирает качество (high / medium / low): плотность пикселей, размер теней, число деревьев. Если во время анимаций кадр устойчиво длиннее ~36 мс, качество снижается само.

Во время работы:

- **Холст не меняет размер.** Он всегда размером с окно, а раскладка (на весь экран / справа / сверху) — это маска `clip-path` и сдвиг кадра камеры (`setViewOffset`). Рисуется только видимая область (scissor).
- **Тени пересчитываются только при изменениях:** солнце, срез этажей, стены планировки.
- **Кадр рисуется только при изменениях.** Сцена ставится на паузу, когда её закрыл текст.
- **Фон планировок вырезан заранее** (`{код}-floor.webp`), картинка декодируется вне главного потока.
- **Поверх WebGL нет `backdrop-filter`.**

Учитываются `prefers-reduced-motion` и `Save-Data`.

### Время суток

Кнопки «День / Вечер / Ночь» ставят реальное положение солнца для координат объекта, 21 июня: 10:30, 19:55 и 23:30 по Бишкеку. Кнопка с часами открывает ползунок времени и месяца. Ночью светятся окна комплекса и соседних домов, витрины, фонари вдоль Южной магистрали, в квартире зажигается свет, на небе — луна и звёзды. Выбор запоминается.

```
src/data/site.js        факты о проекте — единый источник для HTML, JSON-LD и 3D
src/data/plans.js       12 планировок (площади, комнаты, slug как на radian.kg)
src/data/building.js    геометрия комплекса и шахматка (ДЕМО, см. ниже)
src/data/walls.json     стены планировок — генерируется scripts/extract-walls.py
src/data/context.json   дороги и дома вокруг — генерируется scripts/prepare-osm.py
src/pages/render.js     шаблоны страниц, мета, JSON-LD
src/client/scene/       3D: app3d (оркестратор), building, plan3d, env, context, rig, labels, stageui
public/assets/          изображения и планировки (материалы radian.kg)
```

### 3D-планировки по их же иллюстрациям

`scripts/extract-walls.py` находит на иллюстрации планировки чёрные стены и тёмную облицовку фасада, переводит их в полигоны и калибрует масштаб по известной площади квартиры. В 3D пол — сама иллюстрация с вырезанным фоном, стены выдавлены на 3 м. Получается настоящая 3D-версия их планировки, а не выдуманная. При новых планировках положите `{код}.webp` в `public/assets/plans/`, добавьте площадь в `AREAS` и запустите `npm run walls` (`--debug` сохраняет картинки-проверки в `.debug/`).

### Окружение и солнце

Дороги и соседние дома взяты из OpenStreetMap (`data-src/osm-raw.json` → `npm run osm`), поэтому ориентация реальная: Южная магистраль к северу от комплекса, горы Ала-Тоо на юге. Положение солнца считается для координат объекта (UTC+6), ползунок времени и месяца показывает тени. На сайте указана атрибуция «© участники OpenStreetMap».

## Что нужно от клиента

1. **Шахматка.** Реального размещения квартир по этажам на radian.kg нет, поэтому в `src/data/building.js` типы расставлены условно по стоякам (`DEMO_LAYOUT = true`), а на модели стоит пометка «Схематичная модель». Нужна настоящая шахматка: этаж, позиция и тип каждой квартиры. Если будет статус продаж, его можно подтягивать из CRM. Демо-данные не попадают в индексируемый HTML.
2. **Какая часть — апарт-отель.** На модели тёмные объёмы помечены как «апартаменты и апарт-отель». Это предположение, его нужно подтвердить.
3. **Геометрия.** Модель построена по визуализациям, размеры оценочные. При наличии фасадов и поэтажных планов в DWG или PDF можно уточнить `GEO` или заменить модель на GLB.
4. **ID аналитики** (GTM, Метрика) — в `SITE.analytics`, адрес и часы работы офиса продаж, онлайн-форма (см. SEO.md).
5. **Переводы.** Сейчас собрана русская версия; ky, en и ar есть на текущем сайте и переносятся на этот шаблон с теми же slug.

## Деплой (nginx)

`dist/` — статический сайт:

```nginx
server {
  server_name radian.kg;
  root /var/www/radian/dist;
  location / { try_files $uri $uri/ =404; }
  error_page 404 /404.html;
  location /assets/js/  { expires 1y; add_header Cache-Control "public, immutable"; }
  location /assets/css/ { expires 1y; add_header Cache-Control "public, immutable"; }
  location /assets/     { expires 30d; }
  gzip on; gzip_types text/css application/javascript application/json image/svg+xml;
}
server { server_name www.radian.kg; return 301 https://radian.kg$request_uri; }
```

JS и CSS имеют хэш в имени, поэтому их можно кэшировать навсегда.
